# QR-отметка

Сервис для учёта посещаемости в университете через бота и Mini App в MAX. Преподаватель запускает занятие и показывает временный QR-код; студент открывает его в MAX и отмечается; преподаватель получает итоговый список.

[Открыть бота в MAX](https://max.ru/t349_hakaton_max_bot) · [Открыть Mini App](https://app.qr-otmetka.ru)

Frontend и backend P0/P1 реализованы. Локально их можно проверить вместе через Docker Compose; реальные MAX-проверки потребуют зарегистрированного бота, его токена и HTTPS-адреса Mini App.

Публичное развёртывание на `app.qr-otmetka.ru` использует отдельный [`compose.production.yaml`](compose.production.yaml); пошаговая инструкция и двухэтапное назначение первого MAX-преподавателя находятся в [`deploy/README.md`](deploy/README.md). Локальный `compose.yaml` и его demo-значения для публичного сервера не используйте.

## Архитектура и внешние сервисы

| Компонент | Назначение |
| --- | --- |
| MAX-бот и Mini App | Вход преподавателя и студента, открытие QR-ссылки, подписанные данные MAX |
| Frontend (React, TypeScript) | Экраны группы, занятия, QR, списка и подтверждения |
| Backend (FastAPI) | Проверка входа, ролей, состава группы и QR; запись посещаемости и выдача CSV |
| PostgreSQL | Пользователи, группы, занятия, отметки и журнал действий |
| Caddy и nginx | Публичный HTTPS и маршрутизация запросов к приложению и API |

Схема и границы компонентов описаны в [архитектуре](docs/architecture.md). Для публичного режима требуется доступный сервис MAX и настроенный бот с URL Mini App. Локальный demo-режим воспроизводит основной сценарий без MAX.

## Локальный запуск

Нужны Docker Engine и Docker Compose. Из корня репозитория:

```bash
cp .env.example .env
FRONTEND_BUILD_MODE=demo docker compose up --build -d
```

Вторая команда запускает frontend, backend и PostgreSQL вместе. На локальной машине используются порты `8080` (Mini App) и `8000` (API); PostgreSQL наружу не публикуется. Зависимости backend зафиксированы в `backend/pyproject.toml`, frontend — в `frontend/package-lock.json`; сборка выполняется внутри Dockerfile компонентов.

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_PASSWORD`, `JWT_SECRET` | Пароль локальной базы и ключ сессий; для production задать отдельные стойкие значения |
| `ENABLE_MOCK_AUTH`, `DEMO_PASSWORD` | Локальный тестовый вход; в production он отключён |
| `MAX_BOT_TOKEN`, `MAX_BOT_NAME` | Проверка подписанного входа MAX и формирование ссылок бота; в production обязательны |
| `JURY_ADMIN_TOKEN`, `JURY_GROUP_NAME` | Отдельный код для самостоятельного выбора тестовой роли и имя синтетической группы |
| `CORS_ORIGINS`, `DEV_MINI_APP_URL` | Разрешённый адрес клиента и локальная ссылка Mini App |

Серверная конфигурация и HTTPS описаны в [руководстве по развёртыванию](deploy/README.md). Реальные токены и пароли хранятся только в приватном `.env.production` на сервере, не в Git.

## Рабочий сценарий MVP

1. Преподаватель выбирает группу и запускает сессию посещаемости.
2. Mini App показывает динамический QR-код.
3. Студент открывает ссылку в MAX; отметка отправляется автоматически после входа.
4. Backend проверяет пользователя, группу, сессию и срок действия токена.
5. Преподаватель видит список, закрывает сессию и получает результат.

Полный сценарий и ошибки описаны в [документе пользователя](docs/user-scenario.md).

## Данные

Синтетические пользователи и группы для локального demo-режима создаются при запуске backend; они не содержат реальных персональных данных. Рабочие данные хранятся в томе PostgreSQL и остаются после обычной остановки и повторного запуска контейнеров. QR содержит случайный короткоживущий токен, а в базе хранится его хеш. Состав группы можно загрузить из CSV по шаблону `max_user_id,display_name`; посещаемость любой сессии выгружается в CSV.

## Как проверить

Для проверки внутри MAX используйте [инструкцию для жюри](docs/jury-access.md). В локальном demo-режиме используйте тестовый пароль из `.env.example` и учётные записи на экране входа.

| Действие | Ожидаемый результат |
| --- | --- |
| Преподаватель создаёт занятие и показывает QR | Появляется активная сессия и обновляемый QR |
| Студент открывает QR-ссылку | Отметка появляется автоматически, студент видит подтверждение |
| Студент повторяет открытие | Второй записи нет |
| Преподаватель смотрит список и историю | Видны текущая отметка и прошедшая сессия |
| Преподаватель меняет запись и скачивает CSV | Список, аудит и выгрузка отражают действие |

## Известные ограничения

| Ограничение | Следствие |
| --- | --- |
| QR можно переслать | Сканирование не доказывает физическое присутствие в аудитории |
| Состав группы подготовлен в приложении | Принадлежность к университетскому курсу не проверяется по реестру вуза |
| Нет интеграции с электронным журналом | Результат передаётся через CSV |
| Один аккаунт MAX имеет одну активную роль | Для одновременной проверки преподавателя и студента нужны два аккаунта |

## Остановка и повторный запуск

```bash
docker compose down
FRONTEND_BUILD_MODE=demo docker compose up -d
```

Команда `down` не удаляет том БД. Не используйте `down -v`, если нужно сохранить историю занятий.
