# Самостоятельная проверка жюри

Жюри получает **отдельный код доступа** в передаваемой организаторам версии PDF. Это не `MAX_BOT_TOKEN`, не пароль сервера и не доступ к `.env.production`. Код разрешает после подтверждённого входа в MAX выбрать роль для проверки и подключиться к синтетической группе `Проверка жюри`.

## Подготовка командой

1. На сервере сгенерировать независимый код командой `openssl rand -hex 32` и записать результат в `JURY_ADMIN_TOKEN` приватного `.env.production`; оставить `JURY_GROUP_NAME=Проверка жюри`. Ничего из этого не коммитить в Git.
2. Применить конфигурацию backend после попадания этой версии кода на сервер: `sudo docker compose --env-file .env.production -f compose.production.yaml up -d --no-deps --force-recreate backend`.
3. Через два собственных MAX-аккаунта проверить вход, выбор обеих ролей и отметку по QR. Убедиться, что группа не содержит реальных студентов.
4. В финальную версию PDF для организаторов добавить ссылку на [бота](https://max.ru/t349_hakaton_max_bot), этот код и короткую инструкцию ниже. Не включать в PDF токен бота, SSH-данные, JWT, `initData` или содержимое `.env.production`.

Если PDF доступен всем, общий код сможет использовать любой вошедший пользователь MAX. Команда доверяет жюри, но после окончания оценки код следует заменить или оставить `JURY_ADMIN_TOKEN=` пустым и перезапустить backend.

## Инструкция для жюри (текст для PDF)

1. Откройте [бота QR-отметка в MAX](https://max.ru/t349_hakaton_max_bot) и запустите Mini App. Обычное открытие сайта в браузере не передаёт подтверждённые данные входа MAX.
2. В приложении нажмите **«Для жюри»**, введите код доступа из этой презентации и выберите **«Стать преподавателем»** или **«Присоединиться как студент»**.
3. Для проверки полного сценария откройте Mini App через MAX под двумя разными аккаунтами: преподаватель создаёт занятие в группе `Проверка жюри` и показывает QR; студент сканирует его в MAX и получает подтверждение, а преподаватель видит отметку. На этой же странице можно сменить роль и проверить другие экраны.

## Границы механизма

- Код проверяется только backend; во frontend-бандле и ссылках его нет. Страница `/jury` доступна после входа через MAX, а неверный код не меняет роль и не создаёт группу.
- Роль пользователя сохраняется в БД и остаётся после нового входа. Повторный выбор роли не создаёт повторные связи с тестовой группой.
- Это режим самостоятельного тестирования, а не общая административная панель для вуза. Не используйте его для реальных учебных групп.
