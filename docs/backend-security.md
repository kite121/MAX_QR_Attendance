# Безопасность и данные backend-прототипа

Этот документ описывает технические меры прототипа с синтетическими пользователями. Он не является подтверждением готовности к обработке реальных данных университета.

## Минимальные данные

Хранятся внутренний ID, MAX user ID, отображаемое имя, роль, группы и членство, название и время занятия, отметка и время отметки, хеш QR-токена, действия аудита. Телефон, геолокация и IP в PostgreSQL не сохраняются. Пароль локального демо задаётся переменной окружения, не хранится в таблице пользователей. JWT находится только в памяти frontend и действует 30 минут.

## Угрозы и меры

| Риск | Мера | Остаточное ограничение |
| --- | --- | --- |
| Подделка личности | HMAC-проверка `initData` по токену бота и проверка `auth_date`; роль загружается из БД | Похищенный действующий `initData` может использоваться до истечения одного часа; требуется HTTPS |
| Пересылка QR другу | Случайный токен с 10-секундным сроком, в БД только SHA-256 хеш, сервер проверяет MAX ID и членство | QR сам по себе не доказывает физическое присутствие |
| Дубли и гонка с закрытием | Блокировка строки сессии и ограничение `(session_id, student_id)` в PostgreSQL | Необходимо проверять под нагрузкой на целевом хостинге |
| Чужой доступ к группе | На защищённых маршрутах проверяются роль и связь преподавателя с группой | Административный процесс назначения преподавателя будет добавлен позже |
| Подбор токена и частые запросы | Криптографическая случайность токена, ограничение частоты входа и операций записи | Лимит хранится в памяти одного процесса; для нескольких реплик нужен общий стор |
| Утечка через логи | HTTP-лог не включает query string и тела запросов; access-log Uvicorn выключен | Логи внешнего HTTPS-прокси должны быть настроены отдельно |
| Подмена CSV-данных | Проверка размера, кодировки, колонок, роли и дубликатов; одна транзакция; экранирование формул при экспорте | Импорт доступен преподавателю своей группы, его действия следует организационно контролировать |

## Роли и права

Роль преподавателя в демо создаётся серверной загрузкой тестовых данных. Для MAX-пилота первый преподаватель назначается только оператором через `BOOTSTRAP_TEACHER_MAX_USER_ID`. Новый пользователь с корректным MAX `initData` получает роль студента без групп. Преподаватель видит только свои группы и их сессии; студент может отметить только себя в своей группе. Ручные исправления и CSV доступны преподавателю своей группы и фиксируются в audit log. До появления админ-панели настройка реального преподавателя и списка студентов осуществляется контролируемой конфигурацией и импортом тестовых данных.

## Хранение и удаление

Для текущего демо предназначены только синтетические данные. Оператор команды отвечает за удаление тестового PostgreSQL volume после демонстрации; команда `docker compose down -v` удаляет его без восстановления. При пилоте с реальными студентами сначала необходимо согласовать правовое основание, срок хранения, резервные копии, порядок удаления, ответственного оператора и уведомление пользователей. В прототипе нет автоматического удаления или интерфейса запросов субъекта данных. Соответствие 152-ФЗ требует отдельной организационной и юридической проверки до такого пилота.

## Проверки перед публикацией

- Установить собственные `JWT_SECRET`, `POSTGRES_PASSWORD`, `MAX_BOT_TOKEN`, `MAX_BOT_NAME` и HTTPS.
- Выключить mock-вход и заменить demo ID реальными тестовыми MAX ID через защищённый канал.
- Проверить полную цепочку в MAX Mobile и MAX Web, включая `initData`, deep link и срок QR.
- Проверить настройки логов reverse proxy, резервное копирование, ограничение доступа к БД и политику хранения.
- Прогнать тесты и проверить историю Git и образы на секреты.
